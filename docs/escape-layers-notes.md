## Pod Layer System (tram scene)

### Representation

- **clean_scene.png** — z=0 background with all animated objects removed and
  holes inpainted. Generated by `iterative_decompose.py`.
- **RGBA layers** — one per z-indexed object, placed by `bbox` coordinates.
  Each layer's alpha defines its silhouette with 1px feathered edges.
- **sprite_overlays** in YAML — each overlay has: `src` (sprite sheet),
  `bbox` [x0, y0, x1, y1], `frame_count`, `cols`, `fps`, `mode`
  (loop/once/hold), `blend_mode`, optional `empty_bg_patch`, optional
  `mutation` for scheduled re-rolls.
- **layers.json** — manifest with z_index, object_id, layer_path, mask_path,
  scoring history.

### How holes are filled (empty_bg_patch)

Two objects in the tram scene have `empty_bg_patch`: the rain window and the
conductor. The patch is the region behind the object with the object removed
— generated by Imagen inpainting during the decomposition. At runtime, the
patch is composited at z=0 (below all layers) so that when an overlay stops
or is in a "removed" state, the clean background shows through correctly.

The decomposition pipeline (`iterative_decompose.py`) works top-down:
1. Gemini identifies the topmost foreground object (occlusion analysis)
2. SAM3.1 produces a mask for that object
3. Mask is dilated for inpainting quality
4. Imagen inpaints the hole (N candidates, scored by Gemini for no new occluders)
5. RGBA cutout extracted with 1px feathered edge (`mask_ops.cutout --feather`)
6. Protected-object masks prevent inpainting from touching downstream objects
7. Repeat at lower z until no animatable objects remain

Key detail: they deliberately do NOT mask-clamp (force pixels outside the mask
to the original) because hard-compositing at binary mask boundaries creates
visible seams that accumulate across iterations. Instead they trust
MASK_MODE_USER_PROVIDED to keep Imagen's changes inside the mask region.

### How layer edges avoid halos

- 1px feathered edge: SAM mask → binary threshold → 3x3 ellipse dilation →
  Gaussian blur on alpha. Core (inside original mask) gets alpha=255; the
  dilated 1px edge ring gets the blurred alpha value (semi-transparent fringe).
- This prevents the hard-cutout halo where the boundary between the layer and
  background shows a visible seam.
- For animated layers, `difference_matting.py` extracts RGBA overlays by
  solving the compositing equation C_out = alpha * C_fg + (1 - alpha) * C_bg,
  finding the minimum alpha per pixel. This naturally produces soft edges.

### Per-layer states

The pod system uses `mode` for animation lifecycle:
- `loop` — plays continuously
- `once` — plays once then holds final frame
- `hold` — starts paused, plays once when triggered

There's no explicit per-layer state variant system (closed/open/empty).
The pod treats each state as a separate sprite sheet or sprite overlay.
For escape, we need per-object state variants.

## Architecture for Escape

### Key insight: generate-decomposed beats peel-after

We CONTROL scene generation — we don't need to peel objects off a pre-existing
photograph. Instead:

1. Generate **base scene WITHOUT changing objects** — "a wide pastel toy room
   with empty floor where objects would sit, {ESCAPE_STYLE}" — this is the
   clean background by construction. No inpainting needed.
2. Generate each **object state variant** as a standalone chroma sprite on
   magenta (#FF00FF), same as existing pop-sprite pipeline.
3. SAM or Gemini locates the anchor point for each object in the base scene
   (the "where it would sit" region).
4. Chroma-key the sprites to RGBA, composite over base with feathered edges.
5. Judge: "does this look naturally placed, not pasted-on?"

Fallback: if placed sprites look pasted-on, generate the full scene with all
objects (current approach), then peel via pod-style decomposition.

### Manifest structure

```typescript
interface EscapeHotspot {
  id: string;
  box: Box;              // tap target (SAM-located)
  kind: 'search' | 'lock' | 'win';
  gives?: string;
  needs?: string;
  // Layer system
  layer?: {
    anchor: Box;           // placement box for layer compositing
    z: number;             // z-index (higher = in front)
    states: {
      initial: string;     // RGBA sprite: object in default state
      revealed?: string;   // RGBA sprite: container open WITH item visible
      taken?: string;      // RGBA sprite: container open, item GONE
    };
    itemBox?: Box;         // tap target for the revealed item (within the layer)
  };
  // Video clips
  animVideo?: string;      // Veo reveal/transition clip
}
```

### Runtime composite

EscapeGame composites layers over the clean base:
1. Render base scene (static clean background)
2. For each hotspot with a layer, sorted by z:
   - Determine current state variant (initial → revealed → taken)
   - Render RGBA sprite at layer.anchor position
3. State transitions: crossfade between sprite variants (400ms)
4. Veo clips still overlay full-frame during animation, then unmount to reveal
   the new state variant

### State machine (per gives-hotspot)

1. **initial** — object in closed/resting state (chest closed, pillow down)
2. Tap → Veo REVEAL clip plays (pillow lifts, chest opens)
3. **revealed** — container open with item visible; item region (itemBox) glows
4. Tap itemBox → item FLIES to tray (RN Animated spring arc ~600ms)
5. **taken** — container open, item gone; persistent

Win hotspots keep the current `afterScene`/clip → final state flow.

### Generation pipeline

For each room:
1. Generate base scene WITHOUT state-changing objects (clean bg)
2. For each state-changing hotspot, generate object sprites:
   - `initial` — object in closed state on magenta
   - `revealed` — object open with item on magenta
   - `taken` — object open without item on magenta
3. Chroma-key all sprites to RGBA
4. Composite-check: each variant over base, judged for natural placement
5. SAM-locate the item region within `revealed` for `itemBox`
